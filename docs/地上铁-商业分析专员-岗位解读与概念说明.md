## 三、JD 关键词概念详解

### 3.1 聚类 / RFM

**聚类（Clustering）**  
把客户 / 车辆 / 城市等对象，按数据特征**自动分成几类**，事先不贴标签。

- 例子：把租赁客户分成「高频长租 / 偶尔短租 / 价格敏感 / 高价值企业客户」
- 常用算法：K-Means、层次聚类
- 业务价值：不同群体给不同运营策略（定价、续租提醒、优惠）

**RFM** — 经典客户分层方法，看三个指标：

| 字母 | 含义 | 租赁场景举例 |
|------|------|--------------|
| **R** (Recency) | 最近一次租车多久了 | 30 天内租过 vs 半年没租 |
| **F** (Frequency) | 租车频率 | 一年租 12 次 vs 1 次 |
| **M** (Monetary) | 贡献金额 | 累计租金 10 万 vs 5000 |

组合起来就能打标签，例如「R 高 F 高 M 高 = 核心客户，重点维护」。

**与岗位的关系**：对应 JD「客户价值分层」「客户画像标签」「流失预警特征筛选」。

### 3.2 业务 ROI 分析

**ROI = Return on Investment（投资回报率）**

```
ROI = (收益 - 成本) / 成本 × 100%
```

**业务 ROI 分析**：不只看财务账，而是算**某个业务动作值不值得做**。

| 场景 | 要算什么 |
|------|----------|
| 新城市开城 | 投 100 辆车，3 年总成本 vs 预期租金收入 |
| 换更高续航车型 | 采购贵 2 万，但能多出租天数，是否划算 |
| 做企业客户套餐 | 折扣让毛利降 5%，但续租率升 20%，整体 ROI 如何 |

JD 里「可行性数据测算」「简易财务测算模型」指的就是：用 Excel / Python 搭测算表，给业务方「做 / 不做 / 怎么做」的数据依据。

### 3.3 RAG 知识库文档整理与效果评测

**RAG = Retrieval-Augmented Generation（检索增强生成）**

可以理解为：**让 AI 先查公司内部资料，再回答**，减少瞎编。

```
业务问题 → 从知识库检索相关文档 → 把文档片段喂给大模型 → 生成答案
```

| 环节 | 做什么 |
|------|--------|
| **文档整理** | 把 SOP、定价规则、车型手册、历史分析报告等整理成可检索的文档块 |
| **效果评测** | 检索是否相关？答案是否准确？与专家标准答案比通过率多少？ |

**与岗位的关系**：团队可能在建内部问答助手；你负责整理文档、测效果、提改进建议，不一定从零开发 RAG 系统。

---

### 3.4 AutoML 预测模型的训练与结果对比

**AutoML = Automated Machine Learning（自动化机器学习）**

用工具（H2O、AutoGluon、Azure AutoML 等）**自动试多种模型和参数**，选出效果较好的。

**训练与结果对比** 举例：

- 预测「某车下个月出租率」
- 自动试：线性回归、随机森林、XGBoost、LightGBM…
- 对比 MAPE、RMSE、AUC 等指标
- 输出：哪个模型更好、哪些特征最重要

**与岗位的关系**：商业分析岗不一定写复杂深度学习，但要能**跑通 baseline、做模型对比、向业务解释结果**。

### 3.7 AI 诊断 Agent / AutoML 预测项目

**AI 诊断 Agent**  
能**自主多步执行**的 AI 助手，不只答一句话。例如：

```
用户：「为什么深圳 SUV 车型盈利下滑？」
Agent：① 拉取深圳 SUV 数据 ② 对比成本/租金/利用率 ③ 看竞品价格 ④ 输出诊断报告
```

「Agent」≈ 大模型 + 工具调用（SQL、Python、检索）+ 任务规划。JD 里多半是团队在做、你参与测试和场景设计。

**AutoML 预测项目**  
用 AutoML 做的完整项目，例如预测客户流失、车辆残值、某城市需求。简历上写清楚：**预测什么 → 用了什么数据 → 对比了哪些模型 → 业务怎么用结果**。

### 3.8 TCO（Total Cost of Ownership，总拥有成本 / 全生命周期成本）

**TCO = 一辆车从采购到处置，总共花了多少成本。**

```
TCO = 采购成本 + 运营期各项成本 − 处置收入（残值）
```

| 成本项 | 租赁场景含义 | 项目 A 对应 |
|--------|--------------|-------------|
| 采购价 | 车辆买入价格 | `vehicle_asset.purchase_price` |
| 折旧 | 资产价值随时间损耗 | `cost_monthly.depreciation` |
| 维修保养 | 真实运营支出 | `cost_monthly.maintenance`（Zenodo 真实发票） |
| 保险 | 商业车险 | `cost_monthly.insurance` |
| 停车 / 场地 | 车辆停放成本 | `cost_monthly.parking` |
| 处置残值 | 卖二手车收回的钱（减项） | `disposal.residual_value` |

**与月利润 / ROI 的关系：**

```
单车月利润 = 月租金收入 − 月 TCO 各项之和
ROI      = (累计租金 + 残值 − 累计 TCO) / 累计 TCO
```

JD 里「车辆资产收益测算」「单车型/单城市盈利能力复盘」的核心，就是在算 **TCO 能否被租金覆盖**。

### 3.9 月折旧（直线折旧法）

**公式（项目 A 口径）：**

```
月折旧 = 采购价 × (1 − 残值率) / 折旧月数
       = purchase_price × (1 − 0.35) / 60
```

| 参数 | 取值 | 为什么 |
|------|------|--------|
| 折旧月数 | 60（5 年） | 营运车辆常见生命周期 3～5 年，5 年为行业常用假设 |
| 残值率 | 35% | 处置时预计还能卖回采购价的 35%，只摊销剩余 65% |
| 方法 | 直线法 | 简单、可解释，便于跨车型/跨城市对比 |

**例子**：采购价 25,000 USD → 可折旧 16,250 USD → 月折旧 ≈ 270.83 USD。

**面试话术**：「租赁资产按 5 年直线折旧，残值单独在处置环节核算；维保来自真实发票，折旧/保险/停车来自公开行业参数。」
