# 项目 A · 公开数据源说明

> 原则：**核心交易/成本/定价数据来自公开数据集**；缺失字段用**公开行业参数**补充，并在分析中明确标注来源，不随机编造。  
> **表结构、字段口径、ER 图** 详见：[项目A-数据说明.md](./项目A-数据说明.md)

---

## 一、先说结论：有没有「完美真实数据」？

**没有。** 目前找不到一份公开数据，能同时包含地上铁 JD 所需的全部字段：

| 需要的字段 | 公开数据能否直接提供 |
|------------|---------------------|
| 车辆采购价 | ❌ 需用公开 MSRP / 细分市场均价补充 |
| 真实维保成本 | ✅ Zenodo 租车维保数据集 |
| 真实租赁订单/频次 | ⚠️ 部分可用 Getaround 租赁记录 |
| 真实日租金/月租金 | ✅ Getaround 定价数据集 |
| 城市竞品均价 | ⚠️ 需从同数据集按城市聚合，或用公开研报区间校准 |
| 保险/停车费 | ❌ 需用行业公开均值补充 |
| 处置残值 | ❌ 需用公开残值率（如 35%）+ 标准折旧公式 |

**国内新能源租赁数据**（如新能源汽车国家大数据联盟 NDANEV）有「租赁乘用车」类别，但需机构申请，**不能即下即用**。

因此更稳妥的做法是：**用国际公开真实数据做主干 + 公开行业参数补缺口**，简历上写清楚数据来源。

## 二、推荐使用的公开数据集（已下载到 `data/raw/`）

### 数据集 1：租车公司维保记录（核心成本数据）

| 项 | 内容 |
|----|------|
| **名称** | Maintenance Data Set for Car Rental Company |
| **来源** | Zenodo（CERN 开放科研数据平台） |
| **链接** | https://zenodo.org/records/7937227 |
| **文件** | `data/raw/car_maintenance_clean.xlsx` |
| **规模** | 242,269 条维保明细；约 29,995 辆车；67 个城市（CityID） |
| **关键字段** | CARID, Brand, Model, Segment, Year, FuelType, CityID, InvoiceDate, GrandTotal（维保费用） |
| **用途** | 构建 `cost_monthly` 中的**真实维保成本**；按 CARID + 月份聚合 |

> 说明：以 Diesel/Petrol 为主，Electric 仅 23 条。项目可聚焦「租赁资产运营成本分析」框架，面试时说明数据来自国际租车行业公开数据。

## 三、仍需「公开参数补充」的字段（不是随机编造）

以下字段公开数据里没有，需引用**可引用的公开依据**：

| 字段 | 补充方式 | 可引用来源示例 |
|------|----------|----------------|
| 采购价 | 按 Segment + Year 查公开均价 | Statista、IEA、厂商官网 MSRP、二手车均价报告 |
| 月折旧 | 直线折旧法 | 企业会计准则 / 行业惯例（5 年，残值率 35%） |
| 月保险 | 按 Segment 行业均值 | 保险行业协会公开报告 |
| 月停车费 | 按 CityID 城市等级均值 | 各地停车收费公开标准 |
| 竞品均价 | 同城同 segment 车辆 `rental_price_per_day` 均值 | 从数据集 2 自身聚合得出（仍是真实数据） |
| 处置残值 | 残值率 × 采购价 | 二手车残值公开研究（如 3 年残值率） |

**简历 / 面试表述：**

> 「维保费用与租赁定价来自 Zenodo、Getaround 公开数据集；采购价与折旧采用公开行业参数，并在报告中单独标注假设来源。」

## 六、与「自己编数据」方案的区别

| | 原方案（generate_data.py） | 新方案（公开数据） |
|--|---------------------------|-------------------|
| 维保成本 | 随机生成 | **Zenodo 真实发票汇总** |
| 租金 | 公式随机 | **Getaround 真实日租金** |
| 租赁订单 | 随机生成 | **Getaround 真实租赁记录** |
| 采购价/折旧/保险 | 配置参数 | **公开行业参数（有出处）** |
| 业务场景 | 虚构「绿行租赁」中国 B2B | 国际租车/共享出行（框架可迁移） |
